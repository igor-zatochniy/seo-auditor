# SEO/GEO Impact Analytics

У розділі **«Ефективність сторінок»** поєднуються URL поточного SEO-аудиту, імпортована ефективність Google Search Console, GA4-сеанси, окремі GSC AI-покази та перевірені відвідування ботів. Джерела й періоди не підсумовуються між собою.

## Імпорт CSV

Відкрийте GEO-звіт і натисніть **«Імпортувати CSV»**. Період, країна та пристрій задаються для всього файлу. Підтримуються UTF-8, до 2 MiB і 5000 рядків на імпорт.

**GSC Web** приймає `Query` та/або `Page`, `Impressions`, `Clicks`, `CTR`, `Position`. CTR можна подати як частку (`0.12`) або відсоток (`12%`); кома як десятковий роздільник підтримується у CSV із `;`. Наявні значення CTR і Position зберігаються, пропуски залишаються невідомими.

**GA4** приймає `Landing page` (або `Landing page + query string`), `Session source` і `Sessions`. Відносний шлях, наприклад `/pricing?ref=campaign`, розв'язується лише відносно origin, побачених у вихідному аудиті. Сеанси з відомих AI-доменів показуються окремо; класифікатор домену не є доказом, що AI процитувала сторінку. Інші джерела залишаються звичайними GA4-сеансами.

**GSC generative AI** — окрема опційна категорія імпорту з `Page` та `Impressions`; вона не приймає запити, кліки, CTR чи позицію і ніколи не додається до GSC Web. Не імпортуйте до неї ті самі агреговані покази вдруге. Google документує AI Overviews у загальному Search Performance reporting; наявність окремого придатного експорту залежить від джерела даних і не підтверджується самим Auditor ([методика Search Console](https://developers.google.com/search/updates)).

Імпорти GSC/GA4 є користувацькими CSV-даними, а не даними, перевіреними Auditor через Google API. У цій версії немає OAuth-підключення, автоматичної синхронізації чи доступу до акаунта Google.

## Зіставлення URL

Рядки URL мають один зі статусів:

- `exact` — HMAC-ідентичність повного нормалізованого URL збігається;
- `canonical_match` — URL збігається з canonical fingerprint рівно однієї сторінки;
- `ambiguous` — знайдено кілька цілей, тому показник не приписується жодній;
- `unmatched` — відповідного URL у вибраному аудиті не знайдено.

Query string зберігається під час зіставлення. Різні значення параметрів, зокрема токенів, не об'єднуються. У PostgreSQL зберігається лише редагований URL і HMAC fingerprint; сирий URL з імпорту використовується тільки в пам'яті під час зіставлення. GA4 не містить hostname у кожному стандартному значенні Landing page, тому відносні шляхи розглядаються відносно origin джерельного SEO-аудиту; кілька відповідних origin дають неоднозначність, а не автоматичне злиття.

Для старих імпортів без fingerprint доступний fallback за Target ID лише тоді, коли вони належать тому самому SEO-запуску. Після ротації fingerprint-ключа старі міжзапускові URL можуть залишитися незбігнутими; вони не зіставляються за редагованим URL, оскільки це могло б злити різні секретні query values.

## CTR baseline і обмеження

Для вибраного GSC Web-імпорту Auditor обирає найновіший попередній імпорт того самого домену з тією самою країною та пристроєм, період якого завершується до початку поточного. CTR baseline групується за середньою позицією: `1–3`, `4–6`, `7–10`, `11–20`, `21+`. Кліки діляться на покази з вагами за показами, коли метрики доступні.

Орієнтир розраховується як:

```text
покази поточного періоду × max(0, CTR baseline − фактичний CTR)
```

Це резерв, а не прогноз приросту від виправлення. Baseline відображає лише рядки завантажених CSV; GSC може показувати неповний набір рядків. Рівень впевненості знижується для малих вибірок: менше 10 рядків або 1000 історичних показів — низький; від 10 рядків і 1000 показів — середній; від 30 рядків і 10000 показів — високий. Навіть високий рівень не доводить причинний ефект.

GA4 AI referral sessions — сеанси, де `Session source` належить відомому домену AI-продукту. Це не retrieval data й не підтверджене цитування. Verified bot visits беруться з найновішого імпорту журналів і враховують лише записи `matched_range`; непідтверджені спостереження не додаються до них.

Дані API не підсумовуються автоматично з імпортами CSV. Майбутнє підключення Search Console Data API або GA4 Data API має бути окремим OAuth-етапом із дозволом власника ресурсу, захищеним зберіганням refresh token, квотами та ідемпотентним синхронізатором. Search Analytics API також обмежує кількість рядків і не гарантує повного повернення всіх даних ([офіційна документація GSC API](https://developers.google.com/webmaster-tools/v1/searchanalytics/query); [схема GA4 Data API](https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema)).
