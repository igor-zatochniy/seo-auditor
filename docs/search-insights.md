# Посадкові сторінки Google та структура сайту

Дві вкладки доступні у браузерному звіті `/audits/{run_id}`. Початкові SEO-результати не змінюються. OAuth і платних API немає.

## Деталізований CSV GSC

На вкладці **Посадкові сторінки** виберіть origin поточного аудиту та імпортуйте UTF-8 CSV до 4 МіБ / 10 000 рядків:

Імпорт має окремий HTTP-бюджет 30 секунд, незалежний від `FINALIZATION_TIMEOUT`; скасування запиту клієнтом зберігається. Рядки записуються через PostgreSQL COPY у спільній транзакції з метаданими імпорту, без часткового збереження.

```csv
Date,Query,Page,Country,Device,Impressions,Clicks,Position
2026-10-01,chargeback prevention,https://example.com/solutions/prevention/,USA,desktop,100,10,3.2
2026-10-01,chargeback prevention,https://example.com/blog/chargebacks/,USA,desktop,20,1,7
2026-10-02,chargeback prevention,https://example.com/solutions/prevention/,USA,desktop,30,2,5
2026-10-02,chargeback prevention,https://example.com/blog/chargebacks/,USA,desktop,120,12,3
```

`Position` необов'язкова. Інші колонки обов'язкові; дати — `YYYY-MM-DD`, числа — без роздільників тисяч, дробова позиція — із крапкою. Device: `desktop`, `mobile`, `tablet`. Country: коди alpha-2/alpha-3 нормалізуються до alpha-3, наприклад US → USA; невідомі коди відхиляються. Цей модуль приймає лише дані Google Web Search, без змішування Discover, Images чи AI-наборів. Дати зберігаються як дати джерела GSC, без перетворення на часовий пояс Windows.

Потрібні **спільні виміри Date × Query × Page × Country × Device**, а не склеєні незалежні таблиці «Запити» й «Сторінки». Підготуйте деталізований CSV із дозволеного експорту/конектора. Search Analytics API підтримує такі виміри, але не гарантує повернення всіх рядків; вбудованої API-синхронізації Auditor тут не додає ([контракт Google](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)). Приховані запити та обрізаний експорт не відновлюються.

Для кожного запиту, країни й пристрою порівнюються **останні два наявні дні**. Це може бути не два сусідні календарні дні. Лідер — URL з найбільшою кількістю показів; середня позиція не використовується для вибору лідера. Нічия або нуль показів означають невідомого лідера. Частка — покази URL / сума показів імпортованих URL цього сегмента, не унікальна частка видачі. Пропущені URL/дати не доповнюються нулями.

Очікувана ціль береться з обраного GEO-звіту **цього самого запуску й hostname**, включно з останнім ручним вибором target URL. Типово обирається останній такий звіт; можна вибрати інший у списку останніх 200. «Змінилася посадкова сторінка» та «Лідер відрізняється від цілі» — кандидати для перевірки, не доказ канібалізації або падіння позицій. Один день чи неповний CSV не доводять сталий тренд.

Історія показує всі імпортовані URL порціями по 100, запити — по 50. Спостереження для URL поза snapshot теж зберігаються: вони можуть бути фактичними лідерами, але не приписуються іншому target. Ключ запиту нормалізує Unicode NFKC, регістр і пробіли, але не видаляє пунктуацію чи діакритику. Query-параметри URL беруть участь у HMAC-ідентичності; використовується нормалізація target URL самого crawler, без зіставлення за замаскованим URL або довільного canonical merge. Назовні та в нових таблицях URL маскуються. Рядки різних запусків/origin не змішуються. Пошукові запити самі по собі можуть бути конфіденційними: БД і backup лишаються приватним довіреним сховищем.

Повтор того самого імпорту не дублює дані. Перетин Date/Query/Page/Country/Device з іншим файлом відхиляє **весь** новий імпорт; для корекції явно видаліть попередній імпорт і завантажте заміну. Максимум 100 імпортів на один SEO-запуск. Після ротації HMAC-ключа не можна додавати несумісні ідентичності до старої історії того самого origin. Зміни HMAC-ключів не розв'язуються зіставленням замаскованих URL. Для порівняння з GEO-ціллю потрібен хоча б один точний HMAC-збіг імпорту з URL цього аудиту: без підтвердження сумісності ключів результат невідомий, а не хибна розбіжність.

## Структура сайту

Вкладка **Структура сайту** агрегує збережені результати цього аудиту за origin та сегментами шляху. Розділи відкриваються рівень за рівнем із пагінацією по 50; рядок поточного шляху містить його прямі сторінки, не суму всіх дочірніх розділів. Query variants рахуються як окремі targets, але належать тому самому розділу.

- HTTP 4xx/5xx, failed і robots-blocked відображаються окремо; HTTP/failed можуть перетинатися.
- Google noindex береться зі збереженої ефективної індексованості. Якщо перевірку не виконано, показується невідоме значення. Non-self canonical — сигнал для перегляду, не універсальна помилка.
- GEO-покриття: кількість сторінок із цільовими запитами та кількість цих запитів в останньому GEO-звіті поточного hostname, з урахуванням ручних цілей. Запити без цілі показуються окремо, а не штучно розподіляються між розділами.
- GSC показує імпортовані покази/кліки останнього наявного дня або обраної дати. Порівняння кліків із попереднім наявним днем можливе лише для однакового набору сторінок, запитів, країн і пристроїв. Обсяги попереднього й поточного дня показуються навіть при непорівнянних наборах, але «падіння» тоді не стверджується. Немає імпорту — немає даних, не нуль.
- Боти: лише останній імпорт, явно прикріплений до цього Site Crawl через **Повнота обходу → Журнал ботів**, а не сума потенційно перекривних файлів. Verified означає збережений `matched_range`; усі записи й HTTP-помилки показуються окремо. Це не AI-цитування. Без прикріпленого імпорту значення невідомі.

Звіт не є повним переписом сайту. Ліміт обходу, незавершений граф, список URL замість Site Crawl та відсутні результати позначаються як неповне покриття. GSC URL поза snapshot зберігаються в історії посадкових сторінок, але не збільшують кількість перевірених сторінок у дереві. GA4-сеанси та окремі GSC AI-набори не підсумовуються з цими GSC Web показами.

Міграція `044_search_landing_history.sql` лише додає таблиці й індекси; `045_search_import_key_check.sql` додає перевірку незмінності секрету навіть при повторному використанні key_id. Імпорти версії 44 без такої перевірки залишаються читабельними, але нові дані до них не домішуються. Видалення audit run каскадно видаляє його нові імпорти. Відкат нижче 44 видаляє саме ці нові імпорти/історію; перед Down потрібен backup. Старі SEO/GEO-звіти не переписуються.

## Перевірки

```powershell
go test -run TestSearch -count=1 ./...
# DATABASE_URL має вказувати лише на ізольовану тестову БД
go test -tags=integration -run TestSearch -count=1 .
# Окремий тестовий Auditor з ALLOW_PRIVATE_TARGETS=true; не порт 8081
$env:AUDITOR_BASE_URL='http://127.0.0.1:8107'
$env:AUDITOR_ACCESS_TOKEN='<test-server-token>'
node web/e2e/search-insights.cjs
```

Браузерний сценарій створює власний локальний fixture, виконує справжній SEO-аудит і перевіряє CSV, історію, дерево, XSS/маскування, drilldown та мобільну верстку. Встановлення Playwright: `npm ci --prefix web/e2e`; тест використовує встановлений Microsoft Edge. Після тесту його результати залишаються лише в окремій тестовій БД.
