# Міжнародне SEO: hreflang

У звіті SEO-аудиту відкрийте вкладку **Міжнародне SEO**. Дані належать лише його `run_id`: чужі або попередні аудити не використовуються для підтвердження HTTP чи взаємності.

Перевіряються:

- hreflang у document head, включно з неявним `<head>`; inert templates і body не враховуються;
- ISO 639-1, необов'язковий script ISO 15924 і регіон ISO 3166-1 alpha-2; наприклад `uk-UA`, `en-US`, `zh-Hant-TW`; `en-UK` і `en-EU` не приймаються;
- абсолютні HTTP(S) URL, самопосилання, різні URL для одного мовного коду;
- взаємність посилань, HTTP 200 і canonical альтернатив, **якщо ці сторінки сканувалися в тому самому запуску**;
- конфлікт canonical поточної сторінки з її hreflang;
- набори HTML і `<xhtml:link>` у sitemap, якщо обидва джерела оголошують hreflang;
- наявність `x-default` як рекомендація, не обов'язкова умова коректності.

API: `GET /api/audits/{run_id}/international?after={target_id}`. Сторінка містить до 50 результатів і наступний cursor. Доступ захищений наявною локальною авторизацією.

Міграція `023_international_seo.sql` додає nullable evidence до результатів і окремі sitemap-дані з каскадним очищенням. Потрібен backup перед оновленням. Для відкату на binary схеми 22 застосуйте контрольований Down 23 → 22 або restore: Down видаляє лише нові міжнародні evidence та їхній індекс, не SEO/GEO-звіти. Перед запуском старішого binary перевірте точну відповідність версії схеми.

## Межі перевірки

Основою є **Response HTML**, не Rendered DOM. JavaScript-зміни hreflang залишаються доступними у деталях rendering. HTTP `Link`-заголовки наразі не аналізуються цим модулем.

Non-self canonical не є автоматично помилкою: регіональні дублікати тієї самої мови можуть мати спільний canonical. Помилка мовного canonical позначається лише за несумісних відомих мов; інші випадки потребують ручної перевірки.

Для повної перевірки додайте всі мовні версії у список URL або виконайте Site Crawl із sitemap. Cross-domain альтернативи не запускають приховане додаткове сканування: якщо URL відсутній у snapshot, статус — **не перевірено**, а не помилка HTTP чи відсутність взаємності. Звичайні SSRF, robots і per-host правила не обходяться.

Збір обмежений 64 альтернативами на сторінку, розміром URL і JSON-бюджетом. Перевищення позначає evidence як неповне: відсутність тега або return link не доводиться з неповних даних. Старі звіти без evidence потребують повторного аудиту; міграція 23 не вигадує для них дані.

Оригінальні query values не зберігаються в нових полях. Для точного зіставлення, включно з двома різними signed URL, використовуються HMAC fingerprints того самого запуску. Видимі URL маскуються; сам fingerprint не є доказом доступності сторінки.

Вимоги до кодів, взаємності, абсолютних URL, sitemap і необов'язкового `x-default`: [Google Search Central](https://developers.google.com/search/docs/specialty/international/localized-versions).
